# Rent Resilience agent team — runbook

Every command you need to run the 6-role agent team, and how each tool works.
Structure and governance live in `README.md`; this file is operation-only.

The six roles: `schemas`, `ledger`, `dataset` (build lanes), `verifier`,
`teacher`, `advisor`. All commands run from the repo root
(`~/workspace/rent-resilience`) unless noted.

---

## 1. Daily loop

### Start the team

```bash
./scripts/rr-agents.sh
```

Attaches to the running Zellij session `rent-resilience-agents`, or creates it:
a 6-pane layout where each pane runs one role's omp session. Sessions are
resumed, not reset — every role picks up its conversation history from disk.

The advisor pane starts first on purpose: it binds the Pi Link hub (port 9900)
before the other five launch, so the hub race always goes to the coordinator.

### Leave (but keep running)

Detach with `Ctrl-a d` (zellij default prefix is Ctrl-a in this setup; the
status line shows the actual prefix). The team keeps running in the
background. Reattach any time with the same command.

### Stop for the day

```bash
./scripts/rr-session.sh stop <role>      # one role
# or detach, then quit the whole zellij session from inside it:
# Ctrl-a : kill-session  (or exit each pane)
```

`stop` drops a `.stop` flag the runner checks after omp exits, so the pane
finishes its current turn before dying. Nothing is lost; next start resumes.

### Check status

```bash
./scripts/rr-session.sh status
```

Shows each role's state by looking for a live process matching
`--session-dir <dir>`. Running / stopped, per role.

### Reset a conversation (fresh start, history kept)

```bash
./scripts/rr-session.sh new <role>            # one fresh session
./scripts/rr-session.sh new-all               # the four build lanes (keeps teacher + advisor)
./scripts/rr-agents.sh --fresh                # reset ALL six on next start
./scripts/rr-agents.sh --fresh ledger verifier  # reset only named roles
```

A reset never deletes the old session file. It stays on disk under
`.omp/rr-agents/<role>/` and is reachable through the picker:

```bash
omp -r    # session picker; resume any saved session
```

## 2. Zellij survival kit

| Action | Keys |
|---|---|
| Detach (team keeps running) | `Ctrl-a d` |
| Move between panes | `Alt + arrow keys` (or `Ctrl-a` then arrows) |
| Enter scroll/copy mode | `Ctrl-a s` (exit with `q`) |
| Rename a pane | `Ctrl-a ,` |
| Close current pane | type `exit` in the pane (runner's crash guard may restart it; use `rr-session.sh stop <role>` to stop for real) |
| List sessions | `zellij list-sessions` |
| Attach to an existing session | `zellij attach rent-resilience-agents` |

**The EXITED-session quirk** (learned in enviro-grow-pico): if
`zellij list-sessions` shows the session as `EXITED`, attaching lands you in a
dead screen. Delete and recreate:

```bash
zellij delete-all-sessions --yes
./scripts/rr-agents.sh
```

**Never background omp inside a pane.** omp must run in the foreground of its
Zellij pane. Backgrounding corrupts terminal-capability routing (PTY
DA1/OSC11/DECRQM replies get misrouted). This is why the runner script loops
in the foreground; keep it that way.

## 3. Talking to the agents

Each pane IS the agent. Click into a pane (or Alt-arrow to it) and type.
Sessions persist: closing the pane and starting again with `./scripts/rr-agents.sh`
continues the same conversation.

**First turns are scripted.** On a brand-new session, each role gets a
first-turn note baked into its system prompt (generated by
`scripts/rr-agent-terminal.sh` from `.omp/agents/rr-<role>.md`): read your
scratchpad, read the protocol, await Kyle. So a fresh agent opens by orienting
itself; you don't have to re-brief it.

**Scratchpads** are each role's working memory between sessions, at
`docs/agent-team/handoffs/scratchpads/<role>.md`. When you want an agent to
know something permanently, tell it to write it to its scratchpad (or write it
yourself).

**What each agent is for:**

| Pane | You use it for |
|---|---|
| Schemas | schema work in `packages/protocol/schemas/` |
| Ledger | event store, API, signing in `services/api/` |
| Dataset | the synthetic rent-history generator in `simulations/rent-history/` |
| Verifier | hand it a lane handoff; it runs the invariant checklist and reports VERIFIED or FAILED with evidence |
| Teacher | say "next" and it walks the next homework item; paste real terminal output for kata sign-off |
| Advisor | ask "where are we", have it update Team-State, resolve a conflict, review a handoff |

## 4. Teacher: standalone and in-team

In the team layout, the Teacher pane works like any other.

Standalone, in any terminal (no zellij needed):

```bash
./scripts/rr-agent-terminal.sh teacher
```

Both modes share the same session dir (`.omp/rr-agents/teacher/`), so run
only ONE at a time. Standalone has no Pi Link peers; coordination falls back
to the handoff files, which is fine for teaching.

Learning artifacts (teacher-owned, append-only):
- `docs/agent-team/learning/notes.md` — progress + kata results with dates
- `docs/agent-team/learning/reading-log.md` — one line per reading

A completed kata is a ready handoff to the verifier lane: the teacher flags
it, the advisor records it, the verifier turns it into a checklist item.

## 5. OMP session management

Sessions are append-only JSONL files under `.omp/rr-agents/<role>/`. Inside
any omp session:

| Command | What it does |
|---|---|
| `/fork` | clone the session to a new file; original untouched |
| `/branch` | start a new thread from an earlier message, same file |
| `/tree` | navigate session history, label checkpoints |
| `/compact` | shrink context (advisor config does this too) |

From the shell:

```bash
omp -r                          # picker: resume any saved session
omp --resume <path-to-jsonl>    # resume a specific session file
```

The runner auto-resumes: if session files exist, it launches with
`--continue`. That's why resets go through flag files instead of deleting
files.

### Changing a role's model

Two places must agree:

1. `scripts/rr-agent-terminal.sh` — the `model="..."` line in the role's case
2. `.omp/agents/rr-<role>.md` — the `model:` frontmatter line

Edit both, then reset that role (`./scripts/rr-session.sh new <role>`) so the
new prompt file is generated. Model inventory:

```bash
omp models        # all providers/models omp can route to
ollama list       # local + ollama-cloud models
```

Providers worth knowing: `ollama-cloud` (kimi, deepseek, glm families),
`google-antigravity` (claude-sonnet/opus-4-x, gemini 2.5-3.8), `openai-codex`
(gpt-5.6 family), `google-gemini-cli`. Current roster and alternates:
`docs/agent-team/README.md` under "Model roster and alternates".

## 6. Pi Link (agent-to-agent messaging)

The advisor binds hub port 9900 on start; every other role connects as a
client. Roles message each other by name (`link_send` to the advisor, etc.).

The link tools are NOT shell commands. Inside an omp session they are
`xd://` device tools: you write JSON args as content to
`xd://link_send`, `xd://link_list`, `xd://link_prompt`, `xd://link_compact`.
Full contract: `docs/agent-team/Link-Tools.md`.

Rules of thumb:
- `link_list` first: see who is connected before sending.
- `link_send` for fire-and-forget coordination; `link_prompt` when you need
  a response back.
- Link is transient coordination. Durable state always goes through the
  state files and commit-pinned handoffs. If Link is down, handoff files +
  Kyle relaying is the sanctioned fallback.

You don't need to operate Pi Link yourself; the agents use it between them.
Your visibility comes from the registers and Team-State, which the advisor
keeps current.

## 7. Control flags (what rr-session.sh actually does)

The runner checks two flag files after each omp exit:

| Flag | Location | Effect |
|---|---|---|
| `.stop` | `.omp/rr-agents/<role>/.stop` | runner breaks the loop; pane dies, no restart |
| `.reset` | `.omp/rr-agents/<role>/.reset` | runner starts a FRESH session next loop; old file preserved on disk |

You can set them by hand if you prefer:

```bash
touch .omp/rr-agents/ledger/.stop     # stop the ledger lane
touch .omp/rr-agents/ledger/.reset    # fresh ledger session on next exit
```

**Crash guard:** if omp exits within 3 seconds of launch five times inside a
60-second window, the runner stops itself instead of spinning. If a pane goes
quiet with no error, check for that message in the pane and look at
`.omp/rr-agents/<role>/` and the config overlay for the cause.

**Environment override:** `RR_SKIP_HUB_WAIT=1` skips the 5-second Pi Link
hub wait — useful for standalone launches when the team isn't running.

## 8. Handoff lifecycle (how work moves between agents)

1. A lane finishes work and writes a handoff in
   `docs/agent-team/handoffs/` with the exact commit SHA pinned. Never
   "latest".
2. The verifier checks out that SHA, runs the invariant checklist, and writes
   a verification handoff: VERIFIED (with command output) or FAILED (with a
   minimal reproduction).
3. You approve. The advisor records the result in Team-State and the decision
   register.

You are the approval gate. Agents never merge their own work.

## 9. Standing rules the agents already follow

(You enforce these; they're restated here so you can spot violations.)

- The advisor is the single writer of `Team-State.md`, `decisions.md`,
  `conflicts.md`. Specialists report through handoffs; the advisor records.
- Handoffs pin commit SHAs. An unpinned "latest" state is rejected.
- Failed verification is evidence, not failure: FAILED reports with
  reproduction steps are the verifier's entire output format.
- No Claude/AI attribution in any commit or file.
- Secrets only via the `op` CLI (1Password). Never echo emails, KV keys, or
  PostHog distinct_ids into files or logs.
- `npx wrangler deploy` only on Kyle's word.
